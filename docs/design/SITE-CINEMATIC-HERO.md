# [SITE-CINEMATIC-HERO] Landing-page cinematic pipeline hero

> **Host:** [R13](R13-documentation-website.md) documentation website · **Related:** [R14](R14-agent-human-demo.md) conceptual demo · **Status:** Implemented (beta site)

## Objective

Give the landing page a scroll-driven, WebGL-rendered title sequence that walks a
visitor through the real GlyphScramble pipeline in nine beats: the prepared font
exploding into SFNT tables, codepoints sorting into Unicode property buckets, the
seeded Fisher-Yates shuffle, the cmap rewrite and WOFF2 baking on a worker pool,
the one-use variant lease behind an AES-256-GCM token, the two artifact lanes,
the raw-fetch scraper, the human browser, and the recovery boundary.

## Deliberate deviation from R14

R14 lists "canvas-only rendering, 3D effects, video, heavy animation libraries"
among its non-goals. This hero deviates from that non-goal on purpose, for the
landing page only:

- R14's accessible, semantic step explorer remains the canonical conceptual demo
  and a separate deliverable. Nothing here replaces it.
- The hero is a marketing surface. Its job is to make the pipeline memorable in
  under a minute of scrolling, not to be the inspectable reference.
- Every R14 rule about claims still applies to the hero's captions and on-screen
  labels (see below), and the same fixture data drives both.

## What is real in the animation

- The sentence, encoded string, family name, cache headers, and static family
  come from `apps/docs/src/generated/demo-fixtures.json`, generated by the
  packed library at build time.
- The human-render beat draws the **encoded** characters into a canvas glyph
  atlas using the real `GlyphScrambleDemo-runtime-a` `@font-face`. The browser's
  own rasterizer applies the rewritten cmap, so the readable result is a
  genuine decode. No plaintext is swapped in.
- The lowercase bucket's permutation matches the fixture wherever the sentence
  reveals a mapping and is completed without fixed points elsewhere. The
  on-screen Fisher-Yates trace is the swap sequence that produces that exact
  permutation.
- The table ring shows only `cmap` changing and the `head` checksum being
  repaired; other tables are labelled locked.
- There is no "decoder" object anywhere in the scene.

## Claim boundary

Captions live in `apps/docs/components/cinematic-hero/storyboard.ts` and are
unit-tested (`apps/docs/test/cinematic-storyboard.test.ts`) against the wording
rules from R14 and `docs/SECURITY-MODEL.md`: no "blocks", "prevents", "stops",
"all agents", or "every agent"; "DRM" only as "not DRM"; the raw-fetch beat must
say "raw-fetch"; the recovery beat must say "recover". The recovery lane is part
of the main sequence, labelled "recoverable · higher cost, not prevented".

## Architecture

`apps/docs/components/cinematic-hero/`

| File                  | Role                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| `cinematic-hero.tsx`  | Client shell: sticky stage inside a 900svh scroller, DOM captions, mode/tier gating, lazy scene. |
| `cinematic-scene.tsx` | `<Canvas>` and the actor tree. Loaded with `next/dynamic` (`ssr: false`).                        |
| `hero-narrative.tsx`  | Server-rendered ordered narrative: poster content and the screen-reader story.                   |
| `storyboard.ts`       | Beats, captions, scroll ranges, camera keyframes, fixture strings. No three.js imports.          |
| `scroll-progress.ts`  | External progress store written by a passive scroll listener, read by the frame loop.            |
| `capabilities.ts`     | Poster vs. cinematic mode and full vs. lite tier detection.                                      |
| `glyph-atlas.ts`      | Canvas-2D glyph atlas builder (UI font and the scrambled fixture font).                          |
| `glyph-batch.ts`      | Instanced glyph quads (custom shader) and instanced bodies. One draw call per batch.             |
| `timeline.tsx`        | Damped scroll progress, beat/local time, and demand-mode render scheduling.                      |
| `primitives/*`        | Camera rig, lights, fake-bloom sprites, dust, and the per-beat actors.                           |

Scroll progress maps to a beat and a local time; every actor is a pure function
of that state, so scrubbing backwards is exact and screenshots are stable.
`position: sticky` pins the stage; there is no scroll hijacking.

## Modes and fallbacks

- **Poster** (server render, `prefers-reduced-motion: reduce`, no WebGL2,
  `saveData`, WebGL context loss, atlas failure): hero copy plus the nine-beat
  narrative grid. No canvas, no scroller.
- **Cinematic**: same DOM with `data-mode="cinematic"`; the narrative becomes
  visually hidden but stays in the accessibility tree; animated captions are
  `aria-hidden`; the canvas is `pointer-events: none`; hero and outro links are
  `visibility: hidden` when off-beat so they leave the tab order.
- **Tier**: `lite` on coarse pointers, low memory, or few cores (fewer pads,
  particles, bricks, lower DPR, no antialiasing).
- The frame loop runs only while the stage intersects the viewport and the
  document is visible.

## Budget (measured on the static export, gzip)

| Asset                                        |     Size |
| -------------------------------------------- | -------: |
| Landing page eager JS, before                | 182.0 KB |
| Landing page eager JS, after                 | 188.5 KB |
| Lazy cinematic chunk (three + fiber + scene) |   245 KB |

The lazy chunk loads only on `/`, only after hydration, and only in cinematic
mode. It is cached immutably under `/_next/static/`. No third-party requests,
no workers, no `blob:` URLs, no remote fonts or environment maps.

## Verification

- `pnpm test` runs the storyboard/claim tests.
- `pnpm --filter @brip/glyphscramble-demo typecheck`, `pnpm lint`,
  `pnpm format:check`, and `next build` pass.
- Playwright (preinstalled Chromium, SwiftShader) screenshots every beat at
  1440×900 and 390×844, confirms reduced-motion and `--disable-3d-apis` both
  yield the poster with no canvas, walks the tab order, and records layout
  shift during load.

## Open items

- Real bloom (`postprocessing`) was left out; additive sprites stand in.
- Frame-rate targets (55 fps full tier, 30 fps lite) were not measured on real
  GPUs in CI; the software-rendered headless run only proves correctness.
